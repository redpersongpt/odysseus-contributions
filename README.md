# Live raster Markdown image validation

Owned before/after screenshots from the actual authenticated Odysseus Uvicorn app in Google Chrome 151, macOS ARM64. Desktop 1440x1000 and mobile 390x844. The 512x512 bitmap is the repository's existing static/icons/icon-512.png fixture, not a newly generated image.

Baseline is dev 3d01007b9f573af9b4fed8e6e152bafcddeaeba5. source-manifest.json hashes the exact fixed source and screenshots. Before: alt text only, zero image elements. After: one decoded bitmap, width 512 desktop / 332 mobile, no data navigation target. Every case received HTTP 200 through the real /api/chat_stream SSE flow. Two real streaming provider requests per phase; no provider response, app renderer or SSE result was replaced in the browser.

The owned OpenAI-compatible loopback provider deliberately returns the reported Markdown data-URI response shape in two SSE content chunks. No Lemonade instance, model inference or image generation was exercised. Login and session creation used the real API. Submission used the public frontend submit controller and its own composer accessor; native keyboard typing / Send-button activation were not verified. Screenshots were captured before reload. On reload both phases still omit the bitmap under the existing compact-history contract; this change does not repair that limitation or the report's separate model-picker concern.

Browser checks also execute the real DOM sanitizer: the raster IMG.src exception is retained only after the fix; SVG/HTML/JavaScript sources, data href, data srcset, event handlers and scripts are removed. Zero page errors in all four cases. The allowlist validates declared MIME and base64 characters, not decoded bitmap bytes. Independent qualified maintainer review of this sanitization boundary is requested.

The three harness files are the actual local drivers. They use the workspace paths recorded in source-manifest.json, an isolated baseline worktree, fresh per-phase SQLite/data/auth roots, Python dependencies from the app environment, Playwright 1.62.1 and locally installed Google Chrome. Adapt workspace/dependency paths before reproducing. Do not reuse populated runtime roots. Invoke raster-chat-live-check.py before and after with the repository virtualenv Python after preparing the baseline/current checkout; it starts the owned app/provider, runs the browser driver and terminates its process tree. Auth passwords are randomly generated at run time, local mode 0600, and are not published here. No database, provider capture, password or private operator configuration is included.

Focused repository checks: 58 pytest passed (12 new tests; unchanged baseline 5 behavioral failures / 7 controls passed). Existing browser SVG tests ran after installing the matching Playwright Chromium. JavaScript syntax and git diff whitespace checks passed. No full-suite, Docker, Windows or real-provider compatibility claim.
